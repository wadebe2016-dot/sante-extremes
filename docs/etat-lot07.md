# État LOT 7 « DeuxZero » — résumé pour l'architecte

1. **Livré, code complet et testé : 129 tests backend + 64 Flutter, 0 échec, 0 erreur d'analyse.** Sections 1 à 6 du cahier des charges intégralement implémentées (multi-bases + annuaire, rôles/codes hachés scrypt, réinitialisation SMS à quotas, couche Infobip/Nexah/journal, paramètres par association, identité DeuxZero).
2. **Poussé** sur `master` (backend, 9 commits) et `main` (Flutter, 3 commits) ; job CI « Vérification du backend » **au vert**. **NON FAIT — déploiement EC2 et web (§ 8) : aucune clé SSH pour l'instance `sde-api` sur ce poste.** Le workflow vise encore ECS Fargate, pas le systemd actuel, et son étape ECS échoue sur l'authentification AWS OIDC — défaut antérieur au lot, il échoue à chaque push depuis le LOT 6 ; ce push ne déploie donc rien. Reste à faire sur l'instance : `git pull`, `npm ci`, renseigner `PRESIDENT_TELEPHONE` + clés Infobip + `ADMIN_PRODUIT_CODE`, jouer `node scripts/migrer-vers-multi.js`, `systemctl restart sde-api`, puis déposer `build/web`. **Production vérifiée intacte après push** : API `health ok`, `app.santedesextremes.com` HTTP 200.
3. **V1 migration** ✅ sur réplique fidèle de la production reconstruite via les routes publiques : **39 membres, 253 cotisations, 2 100 000 XAF encaissés, 555 000 XAF d'impayés — identiques avant/après**, script rejoué deux fois sans duplication, `data/sde.db` intact, 7 codes repris hachés puis 6 variables supprimées du `.env`.

7. **V11 APK non testé sur appareil** (pas de téléphone ni d'émulateur ici) ; **V12 non applicable** faute de déploiement. Livrables sur le Bureau : `DeuxZero-1.7.0-7-release.aab` (51,4 Mo) et `DeuxZero-1.7.0-7-arm64.apk` (18,8 Mo), `applicationId cm.atlastech.deuxzero`. Build web produit dans `build/web`, non déployé.
8. **POINT BLOQUANT POUR GOOGLE PLAY : les deux binaires sont signés avec la clé de DEBUG** (`CN=Android Debug`) — le projet n'a jamais eu de keystore de release, `build.gradle.kts` pointait encore sur le `signingConfig` de debug. L'APK s'installe et se teste ; l'`.aab` sera **refusé** par Play. Je n'ai pas généré de clé : elle fixe l'identité de l'app pour toujours, exige un mot de passe de votre choix et une sauvegarde hors machine. Dites-moi et je pose `key.properties` + `signingConfigs` en 10 minutes.
9. **Écart assumé §5** : `fenetre_cotisation_debut = 25`, non `1` comme annoncé. La fenêtre en vigueur depuis le LOT 4 s'ouvre le 25 du mois précédent ; poser `1` l'aurait fermée du 6 au 31 et cassé les déclarations anticipées de SDE001 — la règle « ne rien changer pour SDE001 » a primé. Réglable par association. Seul défaut volontairement différent de l'existant : `fiches_sante_actives = 0` (le script pose `1` pour SDE001).
10. **Deux défauts silencieux corrigés au passage, qui auraient rendu le lot inutilisable** : le champ de saisie du code Flutter filtrait `digitsOnly` sur 6 caractères (aucun code de 8 caractères n'aurait pu être tapé, sans message d'erreur), et `X-Association` manquait des `allowedHeaders` CORS et des téléchargements d'export (400 sur toute route métier en version web). Un troisième trouvé par les tests : une réinitialisation visait le mauvais rôle chez un membre en cumulant deux — `roleParTelephone` préfère désormais le code définitif le plus ancien, président exclu.
